# v1.4.0 维护能力设计

范围来自用户已确认的四项建议：单模块更新、版本识别、兼容性记录、可选诊断，以及完整 LLM 交接文档。

- `--build NAME` 只构建所选模块；`--update NAME` 只更新已注入的对应 dylib 和它的元数据，
  不修改 app 主程序/签名、不覆盖其他模块。若未注入，提示全量安装。所有更新保留回滚能力。
- VERSION 为项目版本单一来源。每个构建产物有版本、模块名、源码哈希、构建配方哈希和二进制哈希。
  安装元数据伴随 dylib 一起提交/回滚。状态检查分别显示源码、构建、安装是否匹配；旧无记录安装
  标为 unknown，不冒充新版本。可选 JSON 报告用于后续工具读取。
- 已确认正常的 KeychainFix 查询策略保持不变；新诊断只输出操作、结果码及错误说明、class/DP/group
  是否存在等形状，不输出 service/account/token/数据值。默认关闭。环境变量诊断不会迁移钥匙串。
- `docs/compatibility.json` 保存有明确来源的人工验收基线；采集工具只生成带待验收字段的本地观察，
  不根据 codesign/类存在/测试通过自动标记真实 UI 或账号通过。
- README 为日常入口；AGENTS.md 约束 LLM 必须保留工作基线、先看回归历史；handoff 是现行适配
  操作手册，architecture/compatibility 是当前架构与证据；旧设计/记录明确标为历史，不删除原证据。
- 不主动部署到真实 app，尤其不覆盖已正常登录的 KeychainFix。所有交付先通过自动测试及临时 app
  的真实外部工具演练，未来需要部署时单模块命令可直接使用。
